# Capture release learning

## Overview

A completed release or experiment should produce reusable learning. Without that step, the next iteration starts from memory and opinion instead of evidence.

## What to capture

- What changed.
- Which flag controlled the change.
- Who was exposed.
- What metric or operational signal was used to judge the release.
- Whether the team continued, paused, rolled back, or iterated.
- What should happen to the flag now.

## Agent role

The coding agent can turn release evidence, experiment results, pull request context, and FeatBit history into a concise release summary for the next iteration.
